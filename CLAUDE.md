# Scorcher

Start by reading `docs/VISION.md` (the company's scope and vision: agent testing environments, Scorcher's own agents, the Earth-science suite, principles, pricing, roadmap), then `docs/PLATFORM.md`: the platform vision (Wiki race, Scorcher Sky, Scorcher Tree, a later evolution game, Your Sky and Your Tree), current status and next steps. Scorcher Tree's data and evidence rules are in `docs/tree-data.md`. The suite scope (landing page, agentic Solar/Wind/Geothermal/Engineering platforms, public API, Tree expansions) is in `docs/SUITE.md`; Scorcher Build's architecture, the working harness (`harness/`) and the TypeScript backend Worker (`backend/`; each has its own `npm install`) are in `docs/BUILD-ARCHITECTURE.md`, its security model (what is enforced, what is not, what cannot be claimed) in `docs/BUILD-SECURITY.md`; the evidence review of agentic AI for energy, mining and GIS, with the experimental programme and smallest prototype, in `docs/RESEARCH-AGENTIC-ENGINEERING.md` (verification script and records in `docs/research/`); the domain benchmarks (mining, geothermal, seismic hazard on OpenQuake, solar, wind) and the MCP server in `earthbench/` (shared core; see its README), the phase 1 benchmark in `gisbench/` (Python; its README states what it does and does not show; `npm test` runs it if Python and `gisbench/requirements.txt` are installed); the validation register (every engine decision, its paper or standard, and an automated check) is `docs/VALIDATION.md`, generated by `python -m earthbench.validation`; the technical paper is `mockups/suite/build-paper.html` (served at /build/paper); the visual system is `docs/DESIGN.md`: three styles. Play (race, `/evolve`, Your Sky, Your Tree) keeps the race's plate (EB Garamond, Jost, the logo); Science (`/sky`, `/tree`, `/tools`) uses Atkinson Hyperlegible Next and Mono; Build is its own brand (Mona Sans, Geist Mono). No all-caps or spaced capitals, no italic emphasis, square corners.

- Run `npm test` before committing; it includes browser checks of `/sky` and `/tree` (Playwright).
- Dev server: `node server.js` (http://localhost:3000). Tree data: `node tools/build-tree.js`; check it with `node tools/check-tree.js`.
- The owner uses Windows PowerShell and deploys with `git pull origin main` then `npm run deploy`.
- Never invent a date, support value or citation. Label measured, derived, modelled and illustrative values honestly.
- Keep explanations scientifically accurate and brief. UI should be beautiful and clean; educational content rigorous, well developed and of a good difficulty.
- Work directly on `main` and push there (the owner's instruction, October 2026); commit and push only when asked.
- Refresh TimeTree ages with `node tools/fetch-timetree.js`; full tree build: `node tools/build-tree.js --otol --images --verify`.
